# オールインワン・コピペ用プロンプト

お手元のPC（Windows）でClaude Codeを起動し、下のコードブロックの中身を**丸ごと1回で**貼り付けてください。
事前確認 → ブランチ取得 → 連結テスト → ソフト開発、まで全部この1本で進みます。

---

```text
あなたは「ペアAIプログラマー」というPython製CLIソフトの開発担当です。
以下のフェーズを順番に実行してください。

＝＝＝＝＝ フェーズ0: 事前確認 ＝＝＝＝＝

1. 次のコマンドで両CLIを確認する。
   claude --version
   codex --version
   claudeが無ければ https://claude.com/claude-code のインストール手順を案内して停止。
   codexが無ければ npm install -g @openai/codex を実行する。
2. Codexのログイン状態を確認し、未ログインなら codex login を案内して停止する。
3. リポジトリ masaya031417-coder/samuraidamashii の
   ブランチ claude/claude-codex-integration-rrbcy4 にいることを確認する。
   いなければ以下を実行する。
   git fetch origin claude/claude-codex-integration-rrbcy4
   git checkout claude/claude-codex-integration-rrbcy4

＝＝＝＝＝ フェーズ1: 連結テスト ＝＝＝＝＝

1. 次のコマンドでCodexとの連結を実際にテストする。
   codex exec "1+1の答えだけを返してください。"
2. 回答が返れば「連結OK」と報告して次へ進む。
   失敗したら「Codex未実行」と明記し、失敗したコマンドと
   エラーメッセージをそのまま報告して停止する。
   Codexの回答を推測・模倣することは絶対に禁止。

＝＝＝＝＝ フェーズ2: ソフトの仕様 ＝＝＝＝＝

【コンセプト】
人間にとっての「AIプログラマーの相棒」。
「この資料を元にアプリを作って」のような依頼を受けると、
1. まず自分で調査する
2. 不明点を人間にまとめて逆質問する
3. ClaudeとCodexが得意分野で分担して作業する
4. 難しい判断は両者が合意するまで議論する
という流れで、調査・分析、事業計画・文書作成、ソフトウェア開発をこなす。

【動作フロー】
ステップ1: 依頼受付
  - 人間がタスクと参考資料（ファイルパス等）を入力する
ステップ2: 調査フェーズ
  - Claudeが依頼内容と資料を分析し、必要なら関連情報を調べる
ステップ3: 逆質問フェーズ
  - 着手前に、不明点を3〜5個に絞って人間に一度にまとめて質問する
  - 回答を受けたら要件を確定し、以降は基本的に自走する
ステップ4: タスク分解と振り分け
  - Claudeがタスクをサブタスクに分解し、自動判定で振り分ける
    - Claude担当: 設計・計画・文章作成・リファクタリング・統合・調査まとめ
    - Codex担当: 実装・アルゴリズム・テストコード生成・技術レビュー
    - 会議行き: 判断が分かれうる設計判断、影響範囲の大きい変更、
      事業性とコストが絡む技術選択
  - 振り分けの判定理由を必ずログに残す
ステップ5: 実行フェーズ
  - Claude担当タスクは claude -p で、Codex担当タスクは codex exec で実行する
ステップ6: 会議モード（難易度の高いタスク）
  - Claudeが論点整理と立場表明 → Codexが反論または補強 → 再反論…と
    合意するまで往復する
  - ただし上限は5往復。合意できなければ両者の主張を並べた比較表を作り、
    人間に裁定を仰ぐ
  - 合意または裁定の結果と経緯を議事録として保存する
ステップ7: 統合と納品
  - Claudeが成果物を統合し、人間に最終確認を求める

【成果物の管理】
- 案件ごとに projects/<案件名>/ フォルダを作成し、Gitで履歴管理する
- 各案件フォルダの構成:
    projects/<案件名>/
      brief.md          … 依頼内容と逆質問への回答（確定要件）
      plan.md           … タスク分解と振り分け結果（判定理由つき）
      meetings/         … 会議モードの議事録（meeting-01.md, ...）
      output/           … 実際の成果物（コード、文書）
      log.md            … 実行したコマンドと結果の時系列ログ

【技術要件】
- Python 3.10以上のCLIアプリケーションとして実装する
- claude と codex はサブプロセスとして呼び出す
  （claude -p "..." / codex exec "..."）
- 対話ループを持ち、依頼→逆質問→承認→実行→報告を1つの
  セッション内で完結できるようにする
- 会議モードの往復回数、タイムアウト、担当振り分けルールは
  設定ファイル（config.yaml等）で変更できるようにする
- どちらかのCLIが失敗した場合は、失敗したコマンドとエラーを
  そのままログに記録し、AIの回答を捏造しない
  （Codexが動かなければ「Codex未実行」と明記する）

＝＝＝＝＝ フェーズ3: 開発の進め方 ＝＝＝＝＝

あなた自身もこのソフトの思想に従って開発すること。つまり:
1. まずこの仕様を分析し、不明点があれば着手前に私へまとめて逆質問する
2. 実装計画を立て、私の承認を得る
3. MVPとして最初は「依頼→逆質問→Claude/Codex振り分け→1往復会議→統合」
   が動く最小構成を作る（合意ループ・設定ファイル・上限管理は第2段階）
4. 実装中、設計の重要な判断が出たら codex exec で実際にCodexの意見を取り、
   議論の記録を projects/pair-ai/meetings/ に保存する
5. 動作確認まで行い、実行したコマンドと結果を報告する
6. 完成したらコミットして git push -u origin claude/claude-codex-integration-rrbcy4 する

＝＝＝＝＝ 共通の重要ルール ＝＝＝＝＝

- Codex・Claudeの回答を推測・模倣しない。必ず実際にCLIを実行する
- 破壊的操作（ファイル削除、外部送信、設定変更）は人間の承認なしに行わない
- コスト暴走を防ぐため、1案件あたりのCLI呼び出し回数に上限を設け、
  超えそうなら人間に確認する
- すべての判断（振り分け・会議の結論・裁定依頼）は理由つきでログに残す

＝＝＝＝＝ 最終報告形式 ＝＝＝＝＝

1. フェーズ0の結果（両CLIのバージョン、ログイン状態、ブランチ）
2. フェーズ1の結果（連結テストの成否と実行コマンド）
3. 逆質問と私の回答の要約
4. 実装したファイル一覧と使い方
5. Codexと議論した内容の要点（議事録ファイルへの参照つき）
6. 動作確認の結果
7. 実行したコマンド一覧
```
